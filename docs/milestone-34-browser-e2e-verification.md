## 2. Hardened Production Defect Summary

During the Milestone 34 audit and verification, the following critical defects were identified and resolved:

1. **Eliminated Payment Error Swallowing**:
   - *Previous state*: `processPayment()` caught exceptions from `initiatePayment()` and `confirmBooking()` in local try-catches and logged warnings, then proceeded to mark the booking as confirmed locally and display a fake ticket.
   - *Hardened state*: All payment and confirmation errors bubble up, display explicit failure alerts, dismiss loading overlays, re-enable the payment button for safe retry, and strictly refuse to confirm bookings without backend verification.

2. **Eliminated Fake Booking Fallback**:
   - *Previous state*: If `POST /api/v1/bookings` failed, `goToFood()` caught the error and generated a synthetic `BK...` reference with random UUID.
   - *Hardened state*: Seat reservation failures stop execution, surface backend error details (e.g. 409 conflict, 400 validation), and keep the user on the seat selection step.

3. **Resolved Real ShowSeat UUID Mapping**:
   - *Previous state*: The seat map attempted to match `s.seatNumber === seatId`. Because `ShowSeatResponse` does not carry a `seatNumber` field, matches evaluated to `undefined`, falling back to fake UUIDs (`00000000-0000-0000-0000-...`).
   - *Hardened state*: Implemented sequential mapping between real backend `ShowSeat` entities and the layout grid. Seats without real backend records are marked unavailable and disabled.

4. **Guaranteed Payment Idempotency**:
   - *Previous state*: A new UUID was generated on every payment button click, bypassing backend idempotency protections.
   - *Hardened state*: A persistent `paymentIdempotencyKey` is bound to `state.currentBooking` upon reservation. All subsequent payment attempts and retries reuse this exact key.

5. **Eliminated Mock Auth Fallbacks**:
   - *Previous state*: `verifyOTP()` and `socialLogin()` assigned hardcoded client-side customer credentials without contacting the auth service.
   - *Hardened state*: Removed synthetic user creation; guided user directly to secure email/password authentication.
